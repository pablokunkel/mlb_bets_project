## The one-paragraph answer

The card hits **19.1%** (141/738) since the A1 weights went live on
2026-06-03, and it is not a weighting problem. A one-line baseline — sort
confirmed starters by season HR count, take 8, max 2 per game — hits **19.6%**
on the same days. Every reweighting, every learned model (gradient boosting,
logistic, re-rankers) trained out-of-sample lands between 17% and 21%, inside
the ±1.5-point noise band of a 738-pick sample. The ceiling is lower than the
36-40% the docs still quote: with perfect hindsight, the 10 most HR-prolific
hitters of Jun-Sep homered in **25.1%** of their games, the top 20 in 23.1%.
A great model tops out around 24%. What actually loses picks is structural:
tiny-sample batters scored power 100 (0-for-30), picks that never played
(5.1%), handedness stored as 'R' for the whole league, and an odds capture
that has stored zero rows. Those are what shipped today.

per-pick process looks like at n=8.

### 2c. Things that ARE structural

- **Tiny samples: 0-for-30.** Published picks whose batter had ≤30 season AB
  at pick time: 30, hits 0. Thirteen carried `power_score = 100` (Joshua
  Báez 3 HR in 4 AB, Lázaro Montes 4 AB, Yohandy Morales 5 AB, Nelson
  Velázquez 13 AB…). All `season_batting_fallback` rows. Ranks 9-12 hit
  16.7%. → shipped, PR #130.
- **Dead picks: 38 of 738.** 5.1% never played (not in the posted lineup or
  the game was postponed after the run). → shipped, revalidation workflow.
- **Handedness: 100% 'R'.** `season_batting.bats`, `pick_inputs.bats` and
  every batter dict default to "R" because `/stats` and
  `schedule?hydrate=lineups` never return `batSide`. Real handedness from
  `/people` for the 989 board batters: 410 R / 250 L / 80 S / 12 unknown.
  Starter HR rate by real matchup, 2025-26:

  | bats | vs LHP | vs RHP |
  |---|---:|---:|
  | L | 7.1% | **11.5%** |
  | R | **10.8%** | 8.3% |
  | S | 8.1% | 7.9% |

  The platoon signal was "the pitcher is left-handed" for the whole league,
  i.e. inverted for LHB. Adding real platoon to the ranking moved top-8 by
  −0.3 to +0.5 points (noise), but it is a correctness fix for matchup v1's
  +10 bonus, park L/R skew, wind pull-side and archetype similarity.
  → shipped, B36.
- **Odds capture: 0 rows.** `hr_prop_odds` has been empty since B34 because
  the-odds-api does not carry DraftKings' `batter_home_runs` at all (only
  BetRivers does, intermittently). → shipped, PR #129.
- **Real Statcast (leaky sanity check).** Joining Savant's season-final
  `brl_pa` (look-ahead, so an upper bound): rank(season HR)+rank(prior
  HR)+rank(brl_pa) 21.3%, AUC 0.634 — the best AUC of anything tried. An
  as-of-date nightly pull of real barrel/PA is the next input worth
  building (B1/B6 territory), not another reweight.

## 4. Recommended next levers (not shipped — need a refit + a brief)

1. **Prior-season HR as a talent prior.** Strongest unused input. Cleanest
   home is a shrunk HR/G talent rate `(HR + 0.6·HR_prev + 40·0.115) /
   (G + 0.6·G_prev + 40)` feeding a 7th power input, or the season-HR floor
   on `season_hr + a·prior_hr`. Must be validated through `refit_weights.py`
   on the OOS gate, not this doc's 738-pick replay.
2. **As-of-date real Statcast** (`brl_pa`, `xwoba_contact` already live)
   via the nightly bulk pull, stored beside the synthetic values; then retire
   the `hr_per_pa × 200` barrel synthesis.
3. **Pitcher hand-split HR/9** now that `bats` is real (LHB/RHB HR/9 allowed
   is on the Stats API `sitCodes=vl,vr`).
4. **Expected PA from batting order** — lineup weight is 0 because the old
   table was anti-correlated; a 1-4 vs 7-9 PA multiplier (≈ +8% / −8%) is
   what the logistic fit wants.
5. **Re-anchor the goal.** `How_The_HR_Model_Works.md` and the site copy
   still present 36-40% as the target. The hindsight ceiling on this
   season's data is ~25%; the book's implied probability on the day's
   shortest HR prices is 24-29% before vig.

## 5. How to reproduce

```
python infra/r2_sync.py pull            # from the main checkout, or set HR_BETS_DB
```
Everything in §1-2 is `pick_inputs ⨝ daily_picks ⨝ outcomes` (join on date +
batter_id + game_pk), as-of cumulatives from `outcomes` ordered by date, and
prior season from `season_batting`. The model sweep used scikit-learn
`HistGradientBoostingClassifier(max_iter=300, lr=0.04, max_leaf_nodes=15,
min_samples_leaf=200, l2=1.0)` and `LogisticRegression(C=0.5-1.0)` on
median-imputed, standardised inputs. Real handedness: one batched
`GET /api/v1/people?personIds=…` per 100 ids. Savant:
`leaderboard/statcast?type=batter&year=2026&min=25&csv=true`.
